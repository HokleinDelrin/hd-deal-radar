# 数据源实测结论

> 实测时间：2026-11-09 20:2x，国内出口，curl / requests 双跑。
> 判定标准：能不能程序化、要不要 key、有没有「史低」这个东西。原始响应存 本地 `_probe/`（不入库）。

## 小黑盒（Heybox）—— 已打通，国内最便宜的一档

**为什么值得单独做**：它一个接口同时给出两个别处拿不到的东西。

```
GET https://api.xiaoheihe.cn/game/get_game_detail/?steam_appid=1462040&...签名参数
```

```jsonc
"price": {                       // Steam 官方口径
  "current": "198", "initial": "198",
  "lowest_price": "49.5",        // ← Steam 史低，免费、不用 key
  "lowest_discount": 75
},
"heybox_price": {                // 小黑盒商城
  "cost_coin": 35600,            // 35600 币 = 35.6 元（1000 币 = 1 元，用 original_coin 198000=198 元验证）
  "original_coin": 198000,
  "discount": 82,
  "coupon_info": {
    "coupon_desc": "领券9折", "value": 90, "max_reduce": 3600,
    "final_price": "33"          // ← 用券后到手价，嵌在 coupon_info 里！
  }
}
```

实测《最终幻想7 重制版》：Steam 198 / Steam 史低 49.5 / 小黑盒券后 **33**（-82%）。

### 签名怎么来的

每个请求都要 `hkey` + `_time` + `nonce` 三件套，缺一个直接失败。算法是社区逆向出来的，
这里用 Python 复刻在 `radar/heybox_sign.py`，结构是：

1. `nonce` = 32 位大写 MD5（随机种子即可，不参与服务端校验的语义）
2. 三层字符表映射：固定表 `AB45STUVWZEFGJ6CH01D237IXYPQRKLMN89`
   - `av(str(_time + 3), 表, -2)` ← **注意 +3**，JS 里 `lv[i] = (e,t,n) => ov(e, t+3, n)`
   - `sv(规范化路径, 表)`，路径要补成 `/a/b/` 形式
   - `sv(nonce, 表)`
3. 三段按长度交错拼接，取前 20 字符 → MD5
4. 取 MD5 后 6 位 ascii 码做一轮列混淆（`Km` 那个位运算链），求和 `% 100` 补两位
5. `hkey` = `av(MD5[:5], 表, -4)` + 那两位

### 接口清单（实测）

| 路径 | 参数 | 说明 |
|---|---|---|
| `/game/get_game_detail/` | `steam_appid` | 单个游戏全量。**只有它给 `heybox_price.time_info`（券截止时间）和 `sku_id`** |
| `/game/get_game_infos/` | `appids`（逗号分隔） | **批量**，返回结构同为 `price`/`heybox_price`，但**没有 `time_info`、没有 `sku_id`**；参数写 `steam_appids` 会报 `参数 appids 缺失` |
| 折扣列表 | — | **没找到**。试过 `/game/sale_list/`、`/game/deal_list/`、`/mall/game/list/`、`/mall/sku/list/` 全 404 |

因为小黑盒 web 端没有可用的「折扣列表」接口，**候选池仍然从 Steam 特惠 + CheapShark 出，
再逐个/分批查小黑盒价**。这不影响结果：小黑盒的价值在「同一个游戏哪里最便宜」，不在「发现新游戏」。

### 踩坑

- `final_price` 在 `heybox_price.coupon_info` **里面**，不在 `heybox_price` 顶层；顶层只有 `cost_coin`。
  一开始按顶层取，结果全是 `None`。
- `cost_coin / 1000` 才是元，`original_coin / 1000` 才是原价。
- 请求带 `Referer: https://www.xiaoheihe.cn/` 更像正常流量。
- 批量一次 20 个实测稳定；216 个游戏分 11 批，215 个成功。

## 技术路线（已定）

1. **现价层**：Steam `appdetails`（国区 CNY）逐个拉，每日一遍，落 `prices` 快照 → 自建史低。
2. **国内低价层**：小黑盒 `get_game_detail` / `get_game_infos`，拿「到手价（含券）」+「Steam 史低」，
   到手价作为独立商店 `小黑盒` 进价格表，与 Steam 国区价直接比。
3. **跨店层**：CheapShark 补第三方店（GMG / Fanatical / GOG 等），USD 独立币种，不混算。
4. **史低权威层（可选）**：ITAD，配 `itad_api_key` 后自动生效。走**批量**两个 POST 端点：
   `POST /games/prices/v3`（各店现价，`ids` 一次最多 200）+ `POST /games/history/low/v2`（官方口径史低，同样批量）。
   `Steam appid → ITAD uuid` 的映射落 `meta.itad_map` 长期复用——它才是最稀缺的那次请求。
5. **画像层**：SteamSpy `appdetails.tags`（top-20 + 票数）当 tf，全库 df 当 idf。
6. **免费层**：Epic `freeGamesPromotions`，单独板块，含「即将免费」预告。
7. **不做**：SteamDB、GG.deals、NGA、淘宝/PDD —— 全部 CF/签名/JS 挑战，性价比为负。

## 自动更新（桌面版启动即采，2026-11-15）

桌面版（`app.py`）双击后不再问「要不要更新」，启动就在后台跑一轮，参数与旧版「更新数据」按钮一致：

```
fetch --specials 20 --pages 0 --heybox 20
```

**限速：自动更新最小间隔 30 分钟**（`config.auto_fetch_gap_min`，默认 30）。
判据是「上一轮采集的完成时间」，写在 SQLite `meta.fetch_state` 里，所以关掉应用再打开也认。

- 为什么是 30 分钟而不是 0：本文上表的限速是按「一天一两轮」测出来的（Steam appdetails 单 id 0.3s、
  20 连发无 429；小黑盒批量一次 20 个）。用户反复双击图标时，自动更新就成了对这两家的压力源。
- 手动「立即更新」（托盘菜单 / 网页按钮）**不受这个间隔限制**，但同一时刻只允许一轮；
  两轮并行会把同一批快照写两遍，史低判定会乱。
- 实测：启动轮 20 个 appdetails 耗时 34.5 秒（`last_seconds`）；全部命中 `cache/` 时 0.2 秒。
  状态可从 `GET /api/update` 读到（`running / last_at / last_ok / cooldown_left_min`）。

## 踩坑记录

- **Steam 批量 400**：`appids=1,2,3` 无论是原样、`%2C`、带 `cc=us` 都 400，body 是 gzip Bad Request。只能单 id 串行，间隔 0.3s 实测安全（20 连发无 429）。
- **单 id 可以并发**（2026-11-12 实测）：`appdetails` 虽然不能批量，但多线程各按 0.3s 限速是安全的 ——
  30 个请求 41.1s → 12.0s（3.4×），真实 appid 12 个 5.5s 全部成功、无 429。
  前提是限速计时器按**线程**独立（`http._throttle` 用 thread-local），全局计时器会让线程互相等、并发等于没加。
  默认仍是 1 线程；要开用 `--concurrency 4`。
- **CheapShark 的 id 不是 Steam appid**：`/games?id=1245620` → 404；要先 `/games?steamAppID=1245620` 拿 `gameID`，再 `/games?id=<gameID>`。
- **SteamSpy `average_forever` 全是 0**：玩时长统计停更，别用。
- **wishlist 免登录口子**：老 `wishlistdata` 302 跳首页已废；`IWishlistService/GetWishlist/v1` 无 key 200 但 profile 不公开就返回空 `{}`。
- **GetOwnedGames** 必须 key + profile 公开，否则 401/403。
- **免 key 导出游戏库已经死了**（2026-11-12 复测）：`community/profiles/<id>/games?tab=all&xml=1`
  无登录直接 302 到 `/login`，返回登录页 HTML。唯一不用 key 的仍是 `IWishlistService/GetWishlist/v1`（且要 profile 公开）。
- **profile XML 还活着，用来做预检**（2026-11-12 复测）：`community/profiles/<steamid64>/?xml=1` 和
  `community/id/<vanity>/?xml=1` 都 200，含 `<steamID64>`、`<steamID>`、`<privacyState>`
  （`public` / `friendsonly` / `private`）。所以「填 ID 时先验证 + 告知 profile 够不够公开」可以免 key 做，
  不必等用户申请完 key 才发现库读不出来。
- **ITAD 无 key 是 403 不是 401**（2026-11-12 复测，body 为 `Missing api key`）；`/games/history/low/v2`
  用 GET 打是 **404**（它要 POST，用错方法会误判成「端点不存在」）。
- **ITAD 币种别混**：`country=CN` 下多数店给 CNY，但个别店只报 USD。混着入库会把美元数字当人民币，
  直接把「本地史低」压成假史低 —— 现在的做法是币种不符就丢行并计数（`skipped_non_cny`）。
