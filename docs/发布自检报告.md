### 1.4 联网依赖：会在别人机器上失败的点（已修 1 个硬伤）

#### ❌ 硬伤（已修）：`requests` 是必需依赖，README 却说「零第三方依赖」

实测方法：用 `sys.meta_path` 拦截 `requests`，模拟未安装它的干净环境：

```powershell
python - <<'EOF'
import sys
class Block:
    def find_spec(self, name, path=None, target=None):
        if name == "requests" or name.startswith("requests."):
            raise ImportError("No module named 'requests'")
        return None
sys.meta_path.insert(0, Block())
import importlib
for m in ("radar.config","radar.db","radar.tags","radar.recommend","radar.http","radar.sources.itad","radar.cli"):
    try: importlib.import_module(m); print("  OK   ", m)
    except Exception as e: print("  FAIL ", m, type(e).__name__, e)
EOF
```

实测输出：

```
  OK    radar.config
  OK    radar.db
  OK    radar.tags
  OK    radar.recommend
  FAIL  radar.http: ImportError: No module named 'requests'
  FAIL  radar.sources.itad: ImportError: No module named 'requests'
  FAIL  radar.cli: ImportError: No module named 'requests'
```

再跑 `cli.main(["selftest"])`：**`SELFTEST CRASH ImportError No module named 'requests'`**。

结论：**别人 clone 下来第一条命令 `python -m radar.cli init` 就会崩**。
`radar/http.py:14` 是顶层 `import requests`（整个网络层），另有 `itad.py:33` 也是顶层；
`notify.py:128` / `steamlib.py:174` 是函数内延迟导入（这俩不装也只在用到时报错，不影响主链路）。

**修法（不改业务逻辑、不新增依赖）**：README 如实声明 + 新增 `requirements.txt`（只列 `requests`，它本来就在用，不是新引入）。

> 备选方案（**未采用**）：把 `http.py` 的 requests 换成 urllib 实现真零依赖。这要重写网络层（get/post/status/json/text/raise_for_status）+ 多线程限速联调，属于改业务逻辑，本轮不动。

   这正是这个脚本自己写在头部的教训（顺序必须是扫描→commit→push）。
